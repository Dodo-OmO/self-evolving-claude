# task-flow 反馈（示例）

> 这是一个**示范文件**，展示 feedback-observer 写入的条目格式。真实使用时删掉本文件、按你自己的反馈累积。下面的条目内容为虚构示范。

## 2026-01-01 任务记录要实时回写，不攒到最后

**信号类型**：质疑
**作用层**：实操层
**归并键**：task-md-realtime
**场景**：长任务执行中产生发现 / 决策 / 进度。
**规则**：每完成一步立刻回写任务文档，不攒批——上下文压缩 / 重启时这是唯一续命锚点。
**反例**：连做 5 步才想起回写，中间 context 被压缩，丢失了前 3 步的关键决策。
**原话节选**："你怎么又没记，重启就全忘了"

## 2026-01-03 开工前一次问清，别做到一半回来问

**信号类型**：校准
**作用层**：方案层
**归并键**：ask-upfront-batch
**场景**：自主连续执行模式下，方案对齐到准备开工。
**规则**：所有歧义 / 设计分叉 / 取舍在开工前一次性问完；能自己从代码或合理默认解决的不问。
**反例**：开工后第 3 步才发现一个分叉点没确认，回来问用户——这本可以在开工前一并问清。
**原话节选**："这个为什么不一开始就问"
