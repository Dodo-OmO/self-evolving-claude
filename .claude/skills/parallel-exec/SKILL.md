# 并行执行（parallel-exec）

被项目迭代 / 体检流程在执行阶段调用的共享子能力（接法同 bug-fixer）。目的：省 token + 多线并行提效——块独立时各 worker 不背别块的上下文税。

## 准入闸：判断要不要并行

**第 0 条·边界**：只对「代码」块并行。改 `.md` / skill / CLAUDE.md / hook 等**工程系统文件 → 主对话自己串行做**（这类要全局观，不交给视野窄的 worker）。

代码块过以下四条，**全满足才并行；缺任一条 → 回 solo（主对话串行）**：

1. **块数 2~8**。
2. **文件零重叠【硬线】**：每块先列「文件归属表」= 它要改的确切文件路径。任意两块**没有同一个文件**。有重叠 → 把碰同一文件的块合并成一块，或那部分留主对话。
3. **至少 2 块够大**（按任务文档里**已写出的**内容数，不靠预估）：该块在「实操详细计划」已拆成 **≥3 个步骤**，或「文件归属表」已列 **≥2 个文件**。单文件+单步骤的小修 = 不够大，主对话顺手做。
4. **真独立**：每块在文档写明"依赖哪块的产出"；两块互不在对方依赖里 = 独立。有承接（B 要用 A 新加的函数/字段）→ A+B 合到同一个 worker 内部串行。

## 第 1 步：切块 + 写「切块契约」进任务文档

过闸后在任务文档加一段「切块契约」，给每块写清（这是防各块决定打架的核心）：
- **文件归属表**：块名 → 它独占的文件路径清单
- **共享决定预先写死**：跨块要统一的命名 / 接口签名 / 公共类型 / 谁定义谁调用 / 错误与日志风格——开工前定死，所有 worker 照此办、不许自创；**确无跨块共享则写"无"**
- **每块验收标准**：`tsc --noEmit` 通过 + 该块功能怎么验（具体命令 / 触发场景）
- **依赖标注**：每块依赖哪块（独立块标"无"）

## 第 2 步：并行派 block-worker

1. **主对话先在代码仓 commit 干净基线**（出错可整体回滚）。
2. 一条消息里同时派 N 个 `block-worker`（甜区 3~6），每个任务包必给：
   - **任务文档的绝对路径** + "读其中的「切块契约」段，做属于你的【块X】"
   - 该块的文件归属清单 + 验收标准
3. worker 只改自己那块、用 `tsc --noEmit` 自测、回传证据；不碰 git/build/备份/外部命令，不回写任务文档（这些主对话做）。

## 第 3 步：逐块审 + 合并

- 每个 worker 回传后，**主对话对该代码块派 `code-reviewer` 走两阶段审**（worker 不能自审）。**派发任务包里注明"并行逐块审、审完不要删 review-needed marker"**——整个 session 只有一个 marker、N 块共用，谁先审完就自删会让没审的块提前解锁 stop-gate（这是并行模式必须收回 reviewer 自删权的原因）。
- **每块必须过 code-reviewer 才算完成。** 审查由主对话逐块发起、主对话掌总。
- 全块审过 → 主对话**统一跑一次 `npm run build`** 确认整体编译 → **主对话自己清掉本 session 的 review-needed marker 解锁 stop** → commit（并行模式攒齐一次提交，比 solo 的逐切片 commit 粒度粗，有意为之）。
- 文件零重叠时各块本不撞；万一有未预见重叠，主对话这步调和。

## 第 4 步：BUG 分层（实测出问题时）

- **局部 BUG**（在某块内）→ 主对话**先粗定位根因落在哪块、为什么**（别让 worker 盲试盲改），再按"当前代码状态 + 该块契约 + bug 描述（写清：哪块 / 什么现象 / 期望结果）"**重新派一个新 block-worker** 修（不是续接旧的——新 worker 靠 `Read` 当前代码即可知前一个改到哪，无需口头交接）。
- **跨块 / 要换方案的 BUG** → 不交给视野窄的 worker，**主对话自己接手**走 bug-fixer 四阶段；必要时回方案层重新切块。

## 第 5 步：交用户实测

全块审过 + 整体 build 过 → 对接项目迭代流程的收尾，把每块要用户真机测的**汇成一份清单一次性交用户**（自主连续执行模式下这就是允许的那个统一验收停顿，不是中途逐块多次停）。测出问题回第 4 步。

> 首次实跑留意（本流程已设计为**不依赖**这两点，首次实跑即验证）：① worker 改代码时项目 hook（mark-review-needed / stop-gate）的行为；② 若试用 `isolation: worktree`，注意会话 cwd 非 git 仓、worktree 默认从仓库默认分支拉的坑。
